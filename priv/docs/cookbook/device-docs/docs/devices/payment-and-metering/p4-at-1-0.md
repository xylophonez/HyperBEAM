# ~p4@1.0

The core payment and ledger orchestrator. It asks a pricing device to estimate/price work and a ledger device to decide whether service should be fulfilled.

## When To Use It

- Charge for node services.
- Wrap requests in pre/post payment checks.
- Compose pricing, metering, and ledger devices around ordinary device calls.

## Action Keys

| Key | What it does |
|---|---|
| `request` | Preprocess a request through pricing and ledger checks. |
| `response` | Postprocess a response and settle price where applicable. |
| `balance` | Read balance through the configured ledger device. |
| `p4_pricing-device` | Node option naming the pricing device. |
| `p4_ledger-device` | Node option naming the ledger device. |

## Local Examples

### Configure P4 with simple-pay

```bash
cat > /tmp/hb-p4-simple-pay.flat <<'EOF'
on/request/device: p4@1.0
on/request/pricing-device: simple-pay@1.0
on/request/ledger-device: simple-pay@1.0
on/response/device: p4@1.0
on/response/pricing-device: simple-pay@1.0
on/response/ledger-device: simple-pay@1.0
simple-pay-price: 1
EOF
```

Expected: P4 asks `simple-pay@1.0` for pre-request estimates and post-response charges.

### Check balance through P4

```bash
curl -sS "http://localhost:8734/~p4@1.0/balance?target=USER_ADDRESS"
```

Expected: P4 delegates the balance lookup to the configured ledger device.

### Gate a request before execution

```bash
curl -sS -X POST -H 'content-type: application/json' \
  --data-binary '{"request":{"path":"/~meta@1.0/info/address"},"body":[{"path":"/~meta@1.0/info/address"}]}' \
  "http://localhost:8734/~p4@1.0/request/~json@1.0/serialize"
```

Expected: P4 returns the request body if the price is zero or balance is sufficient; otherwise it returns a payment error such as `402`.

### Charge after response

```bash
curl -sS -X POST -H 'content-type: application/json' \
  --data-binary '{"request":{"path":"/~meta@1.0/info/address"},"body":{"status":200,"body":"ok"}}' \
  "http://localhost:8734/~p4@1.0/response/~json@1.0/serialize"
```

Expected: post-response P4 asks the pricing device for final price and charges through the ledger device.

## Composition

- Use with `~simple-pay@1.0`, `~metering@1.0`, `~faff@1.0`, and operator hooks.

## Trust And Operation

Payment state is operator-controlled local policy unless anchored to an external ledger you verify.
